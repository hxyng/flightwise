# B5 report: frontend

**Premise check:** the premise holds. Tailwind 4.3.3 uses the `@tailwindcss/vite` plugin (its peer dependency is `vite ^5.2 || ^6 || ^7 || ^8`). The CSS starts with `@import "tailwindcss"`, theme tokens live in `@theme` in `src/index.css`, and there is no `tailwind.config.js`.

**Stack:** Vite 8.3, React 19.3, TypeScript 6.0, Tailwind 4.3, Recharts 3.10, framer-motion 14.6, lucide-react 1.x and react-markdown 10. `npm run build` (`tsc -b && vite build`) passes with no TypeScript errors. The JS bundle is about 930 kB (284 kB gzipped), and the chunk-size warning limit is raised to 1200.

## Component map (`frontend/src/`)
- `types.ts`: mirrors `models.py`, plus `Health`. The `delta` AgentEvent type was added from the coordinator's contract update.
- `api.ts`: all HTTP calls, plus the `MOCK` switch.
  - `readSSE()` is a fetch + ReadableStream SSE parser. It handles CRLF, multi-line `data:`, `:` comments and frames split across chunks.
  - `subscribeEvents()` uses an EventSource with a listener per named WatchEvent type, plus `onmessage`.
- `mock.ts`: fixture mode. It holds the scripted agent replay and a fake watcher (details below).
- `App.tsx`: page layout and shared state.
  - Layout: header; main panel with tabs (Agent console / Ask the data); right rail with the watchlist.
  - It owns watch state, the activity feed, toasts and card flashes.
  - It asks for Notification permission on the first watch, and sends browser notifications for status, delay and gate changes.
  - It polls `/api/health` every 15 s.
- `components/`
  - `Header`: wordmark plus health pills (model, Snowflake/DuckDB, status live/mock, search live/mock), each green or amber. Shows a red "api offline" pill on failure and an amber `REPLAY` pill in mock mode.
  - `AgentConsole`: chat input, the 4 suggested prompts (hero cards when empty, chips afterwards) and the live timeline.
    - Timeline steps: thinking, a `tool_call` chip with spinner, scan line and live seconds counter, the resolved result card, the streamed `delta` bubble with typing cursor (replaced by the full `message` text), and errors.
    - A "Working" panel with cycling phase text and a timer covers the 5–10 s model waits.
    - History from the `done` event is sent back on the next turn.
    - The timeline auto-scrolls to follow the stream until the user scrolls up. Stop/abort is supported.
  - `FlightStatusCard`: boarding-pass card.
    - Split-flap flight number, status and gate; route arc (`RouteArc`: SVG Bezier, plane placed at `progress` with a tween); times with the scheduled time struck through when it changes; delay; optional embedded risk gauge; Watch button.
    - Cards in the timeline update live from watcher events.
  - `RiskGauge`: semicircle meter (low/medium/high colors), "based on N flights", and a View SQL toggle.
  - `OfferList`: sortable by price, duration, departure time or stops; CHEAPEST/FASTEST badges; layout animations.
  - `QueryResultView`: Answer (markdown plus table) / Chart / SQL tabs.
    - Uses `QueryResult.chart`; when it is missing, picks a line chart for a time-like x column and bars otherwise.
    - Line charts render as an area chart. Bars mark the best value green and the worst red.
  - `AskData`: "Ask the data" mode. Calls `POST /api/ask` directly and shows the "Powered by Snowflake + open-weight model running locally" badge.
  - `Watchlist`: live cards with split-flap fields and a progress bar, remove (DELETE), an amber flash on change, the activity feed, and a LIVE/RECONNECTING indicator.
  - `Toasts`: animated, auto-dismiss after 6 s. They sit bottom-right on desktop and at the top on phones.
  - `SplitFlap`: tiles flip only for the characters that changed.
  - `SqlBlock`, `Markdown`: supporting components.
- `lib/format.ts`: formatters, and `classify()`, which routes `tool_result.result` to a card by its shape. It accepts a bare `FlightStatus`, `{status|flight, risk|delay_risk}`, `FlightOffer[]` or `{offers}`, `DelayRisk`, `QueryResult`, and `WatchedFlight`/`[]`, and falls back to raw JSON.
- `vite.config.ts`: proxies `/api` to `http://localhost:8000`. It forces `Accept-Encoding: identity` and sets no-buffer headers on event streams.

## How mock mode works
Turn it on with `?mock=1` (`?mock=0` forces it off) or `VITE_MOCK=1`.
- `api.*` calls route to `mock.ts` instead of the network.
- **Agent replay:** the message is matched by keyword (track / find / best time / airline / fallback) to a script.
  - Each script emits thinking → tool_call → tool_result (realistic payloads) → `delta` chunks → message → done.
  - The waits add up to about 6–8 s per turn.
  - The "track" script really adds AA100 to the fake watcher.
- **Fake watcher:** seeded with UA455 (en route) and WN1873 (boards at about 30 s). It emits WatchEvents on wall-clock time.
  - AA100 after it is watched: gate B12→B7 at 7 s, +18 min delay at 14 s, boarding at 24 s, departed at 36 s, en route at 42 s, then `tick` progress until it lands.
- Health reports `gemma4:12b` / Snowflake with mock providers. The `REPLAY` pill makes it visible to judges that this is fixture mode.

## Verified
- In the browser pane at 1024×768 with `?mock=1`, all four prompts ran end to end. The flight card, risk gauge with View SQL, offer list with sorting, line and bar charts, streamed deltas, Ask-the-data tab, live watchlist updates, toasts, feed, Watch button and remove all worked.
- At 375×812 (mobile preset), no horizontal scroll (`scrollWidth == innerWidth == 375`) and the layout stacks.
- **Real (non-mock) path:** tested with a temporary fake backend on :8000, since deleted.
  - `/api/chat` streamed through the Vite proxy unbuffered: chunks arrived about 1.2 s / 1.5 s / 1.9 s / 2.3 s apart.
  - A frame split across chunks, CRLF line endings and `delta` all parsed correctly.
  - Named `/api/events` events reached the feed, and health pills rendered DuckDB and live/mock.
- Screenshots: `docs/frontend-desktop-track.jpg`, `docs/frontend-desktop-askdata.jpg`, `docs/frontend-mobile-track.jpg`.

## Could NOT verify
- Against the real B3/B4 backend. In particular, the exact `track_flight` result shape is a guess; `classify()` tolerates several shapes. I also could not check whether the backend's `added` events carry a `status`; the app re-fetches `/api/watch` after `added` in real mode.
- Browser `Notification` delivery: permission prompts can't be granted in the pane.
- A true 1080p projector layout. The pane's 1440×900 emulation only captured part of the page, so the desktop screenshots are at 1024×768.
- Fonts: Inter and JetBrains Mono load from Google Fonts. Offline, they fall back to system fonts (Segoe UI / Consolas).
- The `oxlint` script from the template was not run.
- In a screenshot taken while the browser pane was hidden, split-flap tiles sometimes rendered blank, although the animations had reported finished. I changed the flip to `animation-fill-mode: backwards` so no 3D transform stays applied afterwards, but I did not see it happen again to confirm the fix.
