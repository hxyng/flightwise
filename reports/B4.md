# B4 report: watcher, API, demo cache

Premise check: sse-starlette 3.2.0 and FastAPI 0.128.8 are installed and work. No false premises.

## Files
backend/flightwise/{watcher.py,api.py,demo_cache.py}, backend/tests/{test_watcher.py,test_api.py}, scripts/dev.ps1

## Routes (all per contract)
POST /api/chat (SSE, event = AgentEvent.type), POST /api/ask, GET /api/flights/search, GET /api/flights/status/{fn},
GET /api/risk, GET|POST /api/watch, DELETE /api/watch/{id} (404 if unknown), GET /api/events (SSE, ping 15s), GET /api/health.
Errors are JSON `{error, detail}` (502 for provider/DB failure, 500 catch-all); never a raw trace. CORS for localhost:5173.
`frontend/dist` is mounted at `/` if present when the app imports.

## Watch event types
added, removed, status_change, delay_change (|delta| >= 5 min), gate_change, tick (every poll per flight).
Messages: "DL204 is now delayed 25 min (was 10)", "AA100 gate changed B12 → C3", "UA88 has departed", "X is back on time (was delayed N min)".
Watch id = `FN-YYYY-MM-DD`; add() is idempotent. Subscriber queues hold 100; overflow events are dropped.
Persistence: data/watchlist.json (written on add/remove/each poll).

## Demo cache
data/demo_cache.json (config.DEMO_CACHE). /api/ask saves successes; on LLM/DB failure or result.error it serves the cached QueryResult,
with answer suffixed "(cached answer: offline mode)" and header `X-FlightWise-Cache: demo`. /api/chat saves the final `message`;
on agent failure it emits a cached `message` (data.cached = true) + `done`, else a friendly `error` + `done`.
Warm: `cd backend && python -m flightwise.demo_cache warm` (needs B2's nl2sql.ask; exit 1 if any of 5 fails).
